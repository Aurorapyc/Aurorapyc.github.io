3x-ui 与 VLESS-REALITY 搭建实录：用 SSH 隧道安全管理面板

发表于2026-11-07|更新于2026-11-07|运维实践

一、这次搭了什么

我买了一台 CloudCone VPS，想搭一个日常自用的节点，也想在 Windows 上方便地管理它。我给 Xray 留了公网 443/TCP，把 3x-ui 面板绑在服务器的环回地址上。需要改配置时，再从本机开 SSH 隧道进去。

传输选了 VLESS + RAW + REALITY，客户端启用 XTLS Vision。我先用 v2rayN 跑通，再拿同一个入站测试 Clash Verge Rev。RAW 的参数少，适合先把连接跑通。XHTTP 和 Hysteria 2 暂时没做同机对比。

实测环境

项目 本次环境
VPS CloudCone 洛杉矶，1 vCPU、系统可见内存约 765 MiB、55 GiB 磁盘
系统 AlmaLinux 9.8，运行内核 5.14.0-687.66.1.el9_8.x86_64
服务端 3x-ui 3.11.0，SQLite，Xray 26.10.21
Windows 客户端 v2rayN；Clash Verge Rev 2.5.10，Mihomo 1.19.33

下面的 IP、UUID、密钥和面板路径都用占位符。版本号是这次复现问题时记录的。

REALITY 的证书是怎么回事

这个入站无需为 VPS 购买域名或申请证书。配置里的 target 指向一个 TLS 站点，客户端用对应的 SNI 发起握手。认证成功时，客户端验证的是 REALITY 的临时可信证书。握手被拒绝并转发到目标站时，客户端可能收到目标站的真实证书。服务端持有 REALITY 私钥，客户端用对应的公钥和 Short ID 完成握手，VLESS 再按 UUID 识别用户。

参考 REALITY 官方说明和 Xray REALITY 配置文档。

二、准备服务器

先用 CloudCone 邮件里的初始密码登录，配置本机的 SSH 公钥，再从新开的 PowerShell 窗口确认可以用密钥登录。

更新系统后，我用 uname -r 确认正在运行新内核。包管理器显示安装了新 kernel-core 时，运行中的版本仍要以 uname -r 为准。

三、安装面板并通过 SSH 访问

安装时怎么选

这次在 VPS 上运行的是 3x-ui 官方安装命令。脚本来自 master，重装时记下安装器实际装出的版本，方便对照菜单和配置行为。3x-ui 官方文档

我选了 SQLite，面板端口填 54321，证书步骤选 Skip SSL，随后对 Bind the panel to 127.0.0.1 only? 选 y。面板 HTTP 只在环回地址上提供，跨网络访问由 SSH 隧道加密。用 x-ui 菜单查看实际的面板端口和 WebBasePath，后面访问时要带上完整路径。

-N 让 SSH 建立转发而不执行远程命令。终端没有提示符是正常的，按 Ctrl+C 会断开隧道。随后在浏览器打开下列地址，用面板账号登录。

四、添加 VLESS 入站和客户端

在 3x-ui 的「入站列表」新增入站。下面是这次实际跑通的设置。

项目 设置
协议 VLESS
监听地址和端口 面板填 0.0.0.0，端口 443
传输 RAW，Mihomo 对应 network: tcp
安全 REALITY
目标与 SNI www.microsoft.com:443，客户端 SNI 选 www.microsoft.com
uTLS 指纹 chrome
嗅探 关闭

生成 REALITY 密钥对后，把私钥留在服务器上。服务端可以设置多个 SNI 和 Short ID，客户端各选一个。Short ID 从允许列表原样复制，在 YAML 里加引号，避免开头的 0 被解析掉。SpiderX 是 Xray 客户端进入爬虫模式时使用的起始路径，这次填 /。

保存入站以后，还要在入站下面点「添加客户端」，生成 UUID，在客户端凭据里把 Flow 设为 xtls-rprx-vision，再导出分享链接。只创建入站时，导出的客户端列表是空的。如果给其他人用，可以为每个人单独添加 UUID，方便分开统计和撤销。

这次 Xray 入站关闭嗅探也能正常使用。Clash 的本地分流由 Mihomo 按自己的规则执行。以后如果要在 Xray 服务端按域名做路由，再根据需求考虑启用嗅探和 routeOnly。Xray 入站与嗅探文档

五、导入客户端

v2rayN

导入 3x-ui 导出的 vless:// 单节点链接，确认地址和端口指向 VPS 的公网 IPv4 和 443。我用这个节点打开 YouTube，先确认服务端的入站和客户端凭据能用。

Clash Verge Rev 和 Clash Mi

电脑的 Clash Verge Rev 和手机的 Clash Mi 都可以导入 Mihomo YAML。下面是我给这个 IPv4 节点用的最小配置。uuid、public-key、short-id 和 SNI 按实际入站填写。它会把交给 Clash 处理的流量交给 VPS 组，方便单独验证这个节点。

电脑端把 .yaml 文件拖进 Clash Verge Rev 的「订阅」页，点配置卡片启用。手机端在 Clash Mi 打开「我的配置」，点「＋」后选择「导入配置文件」。配置里有客户端 UUID，传给自己的设备时用私下的文件传输渠道。Clash Verge Rev 导入说明 · Clash Mi 用户手册

Clash 里遇到的两次故障

  1. 能导入 YAML，测速却失败。 从 Windows 可以连通 VPS 的 443/TCP，v2rayN 也能用。Clash 的 sidecar_latest.log 显示 REALITY authentication failed。我核对了当前入站的 SNI、Short ID、公钥、UUID 和 Flow，再用同一个 Mihomo 内核跑对照测试。原配置握手失败，加上 support-x25519mlkem768: true 后，请求 Google 的 /generate_204 返回 HTTP 204。这条结论对应上面记录的 Xray 和 Mihomo 版本。Mihomo REALITY 参数
  2. 已经能上网，但「代理」页显示「未获取到代理信息」。 最初的规则是 MATCH,CloudCone-LAX，流量直接交给节点，规则模式的「代理」页却没有可展示的组。我加了 VPS 代理组，把规则改成 MATCH,VPS，节点就能在代理页展开并测速。Mihomo 代理组文档

六、IPv6 和端口检查

IPv6 备用节点

我最初想为 IPv6 再建一个 443/TCP 入站，3x-ui 提示原入站已占用这个端口。后来保持原入站，用下面的命令直接测 VPS 的 IPv6 地址。

家里的 Wi-Fi 只有 fe80:: 开头的链路本地地址，route print -6 也没有 IPv6 默认路由 ::/0。切到手机热点后，电脑拿到公网 IPv6，同一条命令返回 TcpTestSucceeded : True。这个结果只证明 IPv6 的 443/TCP 可达。下一步可以复制原节点，只把服务器地址换成 IPv6，再发起一次实际代理请求，确认 REALITY 握手和出网都正常。日常仍用已验证的 IPv4 节点。

核对 VPS 的监听端口

在 VPS 上运行 ss -lntp，再从本机测试公网访问。监听地址用来区分服务绑定在哪，外部 TCP 测试用来确认当前网络能不能连进去。

端口 本次检查结果与用途
22/TCP 公网可连，供 SSH 登录和建立面板隧道。
443/TCP 公网可连，供当前 VLESS + REALITY 入站使用。
54321/TCP 3x-ui 面板只监听 127.0.0.1。本机通过 SSH 转发到它，VPS 公网侧无需放行。
18292/TCP 搭建初期配置的节点端口，后来切换到 443。服务器已无监听，可以撤掉旧放行规则。
2096/TCP 3x-ui 独立的订阅服务端口，这次实测公网可连。仅使用本地 YAML 或单节点分享链接时，可以在面板里关闭订阅服务。

2222 是我电脑上的隧道入口。VPS 侧的放行规则只涉及 VPS 自己的端口。核对规则时，也要看之前是否在云厂商控制台加过一层。3x-ui 订阅服务文档

七、验收结果

  • 用 SSH 隧道可以打开本地 127.0.0.1:2222 上的面板页面，外部 TCP 测试连不上 VPS 的 54321。
  • v2rayN 的 IPv4 节点可以播放 YouTube，Mihomo 经同一入站请求 /generate_204 返回 204。
  • Clash Verge Rev 的「代理」页可以展开 VPS 组，看到并单独测试 CloudCone-LAX。
  • 通过提供公网 IPv6 的手机热点，能连通 VPS 的 IPv6 443/TCP。
