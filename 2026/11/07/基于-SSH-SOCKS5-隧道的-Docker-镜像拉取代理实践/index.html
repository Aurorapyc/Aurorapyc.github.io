基于 SSH SOCKS5 隧道的 Docker 镜像拉取代理实践

发表于2026-11-07|更新于2026-11-08|运维实践

这次让受限网络节点 node-a 上的 Docker 通过一台可连通外网的远端服务器访问镜像仓库。本地的 Docker 命令行操作照常使用，配置改在后台守护进程 dockerd 上。这个办法解决的是 docker pull 访问镜像仓库网络超时的问题，已经启动的容器不会自动使用这个代理。文中的主机名、公网 IP 和镜像源已替换为示例值。

如果平时用 ssh -N remote-panel 映射管理面板，那个隧道由客户端发起。Docker 用的隧道则必须由本地服务器发起，这样 dockerd 才能连到本地的 127.0.0.1:1080。

  • -D 127.0.0.1:1080 在本地开一个 SOCKS5 动态转发监听。应用把目标地址交给它，SSH 再从远端服务器连接目标。
  • -N 只建立转发不执行远程命令，-f 在认证完成后转入后台运行。
  • ExitOnForwardFailure=yes 让 SSH 在端口冲突或无法建立本地监听时报错退出。

4. 在本地配置 Docker 守护进程

下面适用于 Linux 上以 systemd 管理的 Docker Engine 23.0 或更新版本。先用 sudo docker version 确认 Server 版本。docker pull 的联网操作由守护进程发起，所以代理写在 /etc/docker/daemon.json。Docker 守护进程代理文档 · dockerd 配置参考

5. 这次遇到的报错与排查

现象 怎么判断和处理
Connection refused，curl 显示 000 本地连不上 127.0.0.1:1080。先用 ss 检查 SOCKS5 代理进程是否存活。
Permission denied 后出现 root@... password: 本地已连上远端 SSH，但公钥认证没通过。检查公钥是否加入远端的 /root/.ssh/authorized_keys，以及 -i 是否指向本地正确的私钥。
Address already in use 本地 1080 端口已被占用。用 ss 查到占用者 PID，用 ps -ww -p <PID> -o args= 查看命令，确认目标无误后可直接复用原隧道。
401 Unauthorized Docker Hub 的 Registry 已经正常响应。接着用 docker pull 验证完整镜像拉取。

当前隧道是用 ssh -fN 启动的。本地主机重启或网络重连导致隧道断开后，重新执行命令拉起 1080 监听即可，Docker 的代理设置会持久保留在 daemon.json 中。
