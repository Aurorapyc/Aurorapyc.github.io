Tailscale 远程访问与跨账号设备共享实践：IPv6 直连、自建 DERP 与避坑指南

发表于2026-11-08|更新于2026-11-08|运维实践

一、网络拓扑与场景背景

我在家里的 Proxmox VE（PVE）宿主机上部署了应用虚拟机（运行各类 Web 与容器化服务）。为了在外部（学校校园网、手机热点等）能够随时安全访问家里的内网服务，并支持把特定单台虚拟机共享给朋友或备用账号，我采用了基于 Tailscale + 自建阿里云 DERP 中继 的异地组网架构。

文中的公网 IP、个人邮箱与私有域名已作脱敏替换，复现时请替换为你自己的实际参数。

二、IPv4 请求走 IPv6 直连的封装流程

以在外部浏览器打开内网 Web 服务地址 http://192.168.20.110:5212 为例：

  1. 浏览器发起目标为 192.168.20.110:5212 的 IPv4 TCP 请求，匹配 PVE 发布的 192.168.20.0/24 子网路由，由 Windows 交付 Tailscale 虚拟网卡。
  2. 两端直连时，Windows Tailscale 将加密后的内层数据封装进发往 PVE 公网 IPv6 的 UDP 数据包中。
  3. PVE 接收并解密后，通过 vmbr0 局域网转发给虚拟机；响应数据按原路返回。

Tailscale 子网路由说明 · Tailscale IPv6 说明

三、为什么手机热点能直连，校园网却走中继？

  • 手机热点。Windows 和 PVE 都有可用的公网 IPv6，两端建立了 UDP 直连。从 Windows 发起探测时，via [240e:…]:41641 显示的是 PVE 的公网端点。后续 16 次直连探测的中位数是 45 ms，其中 13 次在 30–50 ms，最高 110 ms。
  • 校园网。Windows 的 netcheck 显示 IPv6: no 和 MappingVariesByDestIP: true，后者表示公网映射会随目的地变化。家里宽带处于运营商 CGNAT 后面，家里路由器的端口映射只覆盖家里这一层。这轮 IPv4 打洞没成功，Tailscale 自动走 DERP(aliyun)，探测约 20 ms。 Tailscale 连接诊断
  • 之前有一次 IPv4 直连，探测约 6 ms。后来 PVE 公布的公网 IP 和候选 UDP 端口都发生了变化。现有日志无法确定当时为什么打通，也无法定位后来是哪一层影响了打洞。 Tailscale NAT 打洞原理

45 ms 和 20 ms 分别来自手机热点和校园网。虽然热点直连绕过了 ECS，往返时间仍受接入链路和公网路由影响，现有测试无法确定额外延迟出在哪一段。 Tailscale 连接类型

四、PVE 宿主机 IPv6 接收通告内核调优

内核参数配置

PVE 的 vmbr0 原来是 accept_ra=1。当接口开启 IPv6 转发时，Linux 在此模式下会忽略路由器通告（RA）。改为 accept_ra=2 后，接口即使开启 IPv6 转发也能接收通告。本次 autoconf 已经是 1，收到前缀后即可自动配置地址。

参数项 取值 作用
net.ipv6.conf.vmbr0.accept_ra 2 即使系统开启了转发，仍强制接收路由器的 RA 通告
net.ipv6.conf.vmbr0.autoconf 1 允许网卡根据接收到的 IPv6 前缀自动配置无状态公网地址（SLAAC）

五、跨账号设备共享（Node Sharing）与 Grants 授权

当把 vm-apps 单机共享给新账号（guest@example.com）时，需要注意以下边界规则：

1. 单机共享不传递子网路由

Tailscale 设备共享（Share node）仅赋予接收方访问被共享单机本身虚拟 IP（100.113.124.120）的权限，PVE 发布的 192.168.20.0/24 子网路由不会随共享传递。新账号在 tailscale status 里找到共享设备后，可用它显示的 Tailscale IP 访问。本次是 100.113.124.120。如果启用了 MagicDNS，也可用设备的完整名称，例如 vm-apps.tail000000.ts.net，其中 Tailnet DNS 后缀需换成自己的。 Tailscale 设备共享机制

2. Grants 访问策略设计

共享可见、网络策略放行、系统 SSH 认证三者相互独立：

  • "src": ["*"] 会覆盖有访问资格的共享用户；
  • 若想限制范围，autogroup:shared 可用来匹配所有共享进来的用户，指定邮箱则能把授权范围缩小到单个接收方；
  • Grants 授权会累加。把下面的规则加入主 Tailnet 的 grants 数组时，还要检查原来的宽泛规则。只要旧规则仍允许该接收方访问其他端口，新增的 tcp:22 就不会收回那些权限。 Tailscale 共享访问策略

目标机若使用系统原生 OpenSSH，TCP 22 连通后由 Linux sshd 验证凭据；若开启了 Tailscale SSH，则另需策略文件中的 ssh 规则放行。 Tailscale SSH 文档

六、自建 DERP 中继踩坑与恢复配置

新账号接受 vm-apps 的设备共享后，SSH 起初超时。调整两边的 DERP 配置并关闭 ECS 的本地客户端校验后，新账号用 100.113.124.120 成功登录 SSH。多个设置在同一轮调整，无法单独确认是哪项改动恢复了连接。

  1. 排查时同步了两边的 DERP 区域。主 Tailnet 配置了 Region 900，vm-apps 的 HomeDERP 是 900，新账号所在的 Tailnet 最初没有这个区域。排查时把相同的 derpMap 加入两边。官方仍将跨 Tailnet 设备共享列为自建 DERP 的不支持项，这次恢复属于当前环境的实测记录。 Tailscale 自建 DERP 限制
  2. 域名 SNI 与纯 IP 探测差异：携带 derp.example.com 的 SNI 时，TLS 连接被重置。直接用公网 IP 发起的 HTTP 测试收到 200。现有记录无法确认重置来自哪一层，也无法确认是否与机房拦截有关。HTTP 响应和 DERP 会话应分别验证。 阿里云 ECS 访问排查
  3. 开启客户端校验时中继拒绝新账号节点：ECS 的容器日志出现 not authorized (not found in local tailscaled)。开启 DERP_VERIFY_CLIENTS 时，derper 会用本机 tailscaled 检查客户端是否对其可见。排查期间临时关闭了这项校验（设为 false）。 DERP 客户端校验说明

上一篇 在阿里云 ECS 自建 Tailscale DERP：从美国中继到 20 ms 记录的是同一 Tailnet 内的常规部署，用域名证书并开启客户端校验。下面这组值用于记录这次跨账号排查时的配置。

恢复时使用的临时配置

配置项 取值
两个 Tailnet 的 derpMap Region ID: 900，Region Code: aliyun，Node: 900a
节点定义 HostName: "198.51.100.20", DERPPort: 12443, STUNPort: 3478, InsecureForTests: true
容器服务 /opt/derper/docker-compose.yml，镜像 ghcr.io/yangchuansheng/derper:v1.102.3
监听与端口 DERP_ADDR=:12443，DERP_HTTP_PORT=-1，DERP_DOMAIN=derp.example.com
准入参数 DERP_VERIFY_CLIENTS=false

安全警示：InsecureForTests: true 会跳过 DERP 服务端证书校验。关闭 DERP_VERIFY_CLIENTS 会移除基于本机 tailscaled 的准入检查。如果端口对公网开放且没有其他准入限制，第三方客户端可能使用中继并占用 ECS 带宽。长期运行应使用可验证的证书并限制中继准入。需要跨 Tailnet 设备共享时，优先验证 Tailscale 官方 DERP 路径。 TLS 校验源码 · DERP 客户端校验

七、文件传输路径与带宽

访问方式 如何判断传输路径
http://192.168.20.110:5212 通过主账号的子网路由访问内网 Web 服务。查看 PVE 的连接状态，direct 表示绕过 ECS，relay "aliyun" 表示经 ECS 中继。
http://100.113.124.120:5212 访问 vm-apps 自己的 Tailscale 地址。查看 vm-apps 的连接状态。
https://cloud.example.com 公网域名示例。如果通过 Cloudflare Tunnel 发布，应查看 Tunnel 的公开路由、连接器位置和回源地址。本文尚未核对实际回源路径。 Cloudflare Tunnel 路由

从外面上传到家，主要看外出端的上行和家里宽带的下行。从外面下载家里的文件，主要看家里的上行和外出端的下行。直连时，两端带宽和公网路径都会影响实际速度。中继时，ECS 的出网带宽和中继可用吞吐也可能成为瓶颈。

如果上传界面显示的是 1.2 MB/s，换算约为 9.6 Mbps。那次上传的瓶颈还没有定位。要判断是否经过 ECS，可以在传输期间查看对应节点的 tailscale status。

1. 主账号验证 PVE 子网路由

Windows 保持主账号配置。先看 Windows 到 PVE 的路径，再用内网 Web 服务的地址验证子网转发：

via [240e:…]:41641 是到 PVE 的公网 IPv6 直连。via DERP(aliyun) 表示经过阿里云中继。这次用手机热点实测，PVE 显示 IPv6 直连，内网 Web 服务返回 HTTP 200，同时 PVE 的 Tailscale 收发计数增加。 Tailscale 连接类型

2. 新账号验证共享虚拟机 SSH

Windows 切到新账号配置，目标改为共享的 vm-apps：

tailscale debug derp aliyun 验证客户端能否与自建 DERP 建立连接，tailscale ping 显示本轮到 vm-apps 的实际路径。TcpTestSucceeded : True 表示 TCP 22 可达，最后以成功进入 SSH 会话为准。 Tailscale TCP 连通性排查
